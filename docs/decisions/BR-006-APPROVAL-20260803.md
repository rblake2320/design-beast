# BR-006 — VRAM-aware external resource admission

Decision date: 2026-08-03
Decision: **APPROVED by the user in the active Beast-core build thread**

## Authority

The user directed implementation of the ten-item Beast-core plan with “let's get
it done.” That plan explicitly included a resource governor preventing Ollama,
Unreal, video models, and other GPU workloads from overwhelming the RTX 5090.
This followed the user's earlier standing requirement that completed work must
not leave more running than VRAM can handle.

## Approved scope

- Measure live NVIDIA free/used VRAM before admitting new Beast GPU work.
- Keep the existing durable Beast Studio heavy/light lease scheduler.
- Protect an explicit VRAM reserve and fail closed when live state is unknown.
- Expose read-only operator checks through the Beast CLI.
- Never terminate Unreal, a game, Ollama, or another user process automatically.
- Retain tests and real admission receipts before describing the behavior as
  verified under multiple live workload combinations.

## Claim boundary

Admission is a point-in-time guard. It cannot prevent an unrelated application
from allocating VRAM after admission, and it is not a generalized performance or
out-of-memory guarantee until measured under repeated mixed workloads.
